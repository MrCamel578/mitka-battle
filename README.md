# Митька-Battle — серверные аккаунты

## Публикация в интернете (Render)

Конфигурация `render.yaml` уже добавлена. Она включает Node.js-сервис, автоматически создаваемый секрет сессий и постоянный диск для базы SQLite. Для постоянного диска нужен платный тариф Render; не используй бесплатный сервис с временной файловой системой для этой версии, иначе база аккаунтов может исчезнуть при перезапуске или новом развёртывании.

1. Создай аккаунт на GitHub и новый пустой репозиторий.
2. Загрузи в репозиторий **содержимое** этой папки: `server.js`, `package.json`, `render.yaml`, `.gitignore`, `.env.example`, папку `public/` и `README.md`. Не загружай `data/`, `.env` или `node_modules/`.
3. В Render выбери **New + → Blueprint**, подключи репозиторий и подтверди создание сервиса по `render.yaml`.
4. Дождись окончания сборки и статуса **Live**. Render выдаст публичный адрес вида `https://имя-сервиса.onrender.com` — отправь его друзьям.
5. В Render → Environment проверь, что `NODE_ENV=production`, `SESSION_SECRET` задан автоматически, а `DATA_DIR=/var/data`. Не публикуй значение `SESSION_SECRET`.
6. Проверь регистрацию тестового аккаунта, перезагрузку страницы, выход и повторный вход. Затем можешь отправить ссылку друзьям.

Если у тебя нет постоянного диска в тарифе, не запускай публичную версию с важными аккаунтами: SQLite-файл должен храниться на постоянном диске. Не удаляй и не пересоздавай диск после регистрации пользователей.

## Локальный запуск

Нужен Node.js 20 или новее.

```bash
npm install
```

Linux/macOS:
```bash
SESSION_SECRET="$(node -e \"console.log(require('crypto').randomBytes(48).toString('hex'))\")" npm start
```

Windows PowerShell:
```powershell
$env:SESSION_SECRET = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(48))
npm start
```

Откройте http://localhost:3000. Не открывайте `public/index.html` напрямую через `file://` — сайт должен загружаться через сервер.

## Что есть

- Регистрация и вход на сервере.
- Пароли хранятся в SQLite только как bcrypt-хеши (12 раундов); открытые пароли не сохраняются.
- Серверные сессии с HttpOnly и SameSite cookie; хранилище сессий — SQLite.
- Ограничение частоты попыток входа/регистрации.
- Сохранение игрового профиля в SQLite и восстановление сессии после перезагрузки страницы.
- Общий рейтинг игроков.
- Обложки кейсов и текущая визуальная часть оставлены в исходном HTML без изменения данных обложек.

## Важное ограничение

Учётные записи, хеши паролей, сессии и сохранение профиля серверные, но игровая логика кейсов/апгрейда пока рассчитывается в браузере, а профиль отправляется серверу для сохранения. Поэтому баланс и инвентарь ещё можно подменить через инструменты разработчика. Для публичной экономики без читов нужно перенести открытие кейсов, продажу и апгрейд в серверные транзакции и проверять результат только на сервере.
