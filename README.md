# МитькаBattle — обновление с PostgreSQL API

## Что добавлено

- Авторизация и профили на сервере: аккаунт, баланс, инвентарь и настройки доступны после входа с другого устройства.
- Игровые операции на сервере с PostgreSQL-транзакциями: открытие кейса, апгрейд, продажа предметов, ежедневный бонус и контракты.
- Вероятности кейсов рассчитываются по той же таблице весов, которая используется в интерфейсе. Множители стоимости дропа скорректированы, чтобы дешёвые кейсы были полезны для старта, но не создавали гарантированную прибыль.
- 131 скин в каталоге и 38 кейсов.
- Админ-роль, просмотр игроков с активностью за последние 90 секунд, выдача денег/скинов, бан/разбан и журнал админ-действий.
- Бан проверяется сервером для игровых операций; интерфейс показывает сообщение о бане.
- Результат апгрейда и списание предметов фиксируются в одной транзакции до анимации, поэтому обновление страницы не отменяет операцию и не дублирует ставку.

## Архитектура бесплатного размещения

Netlify обслуживает статический интерфейс, Render запускает Node.js API, а Supabase предоставляет PostgreSQL. Один только Netlify Static Hosting не запускает `server.js`, поэтому API необходимо развернуть отдельно.

### 1. Supabase

1. Создайте проект Supabase.
2. В Settings → Database скопируйте URI подключения PostgreSQL.
3. Не публикуйте URI и не добавляйте его в GitHub.

### 2. Render

1. Загрузите содержимое этой папки в GitHub.
2. В Render создайте Web Service / Blueprint из репозитория.
3. Задайте `DATABASE_URL` как PostgreSQL URI Supabase.
4. В переменной `ADMIN_PASSWORD` задайте желаемый пароль администратора. Для указанной конфигурации используйте пароль, который вы указали в запросе, и храните его только в настройках Render, не в репозитории.
5. `SESSION_SECRET` генерируется автоматически. Оставьте его секретным.
6. После запуска проверьте `https://ВАШ-СЕРВИС.onrender.com/api/me` — без входа ожидается `{"user":null}`.

При первом запуске сервер создаст таблицы и назначит роль администратора пользователю из `ADMIN_USERNAME`/`ADMIN_PASSWORD`. Эти переменные должны быть заданы до первого входа администратора.

### 3. Netlify

1. Загрузите папку `public/` как сайт Netlify.
2. Откройте `public/_redirects` и замените `YOUR-RENDER-SERVICE.onrender.com` на фактический хост вашего Render-сервиса. Пример: `/api/* https://mitka-battle-api.onrender.com/api/:splat 200`.
3. Перезапустите deploy Netlify.
4. Проверьте регистрацию, выход, вход и открытие кейса. Вкладка Network не должна показывать ошибки для `/api/*`.

Netlify проксирует `/api/*` на Render, поэтому браузер обращается к API через домен сайта и сессионная cookie остаётся доступной сайту. Не меняйте путь `/api`.

## Примечания

- Данные существующих аккаунтов, которые жили только в `localStorage` старой версии, нельзя безопасно перенести автоматически: там нет исходного пароля, который можно зарегистрировать на сервере. Такие пользователи должны создать серверный аккаунт заново. Старый `localStorage` не считается источником истины.
- Активным считается пользователь, чей heartbeat был получен в течение последних 90 секунд. Вкладка сайта должна оставаться открытой.
- Каталог и цены — внутриигровая модель для этого сайта, а не официальный live-прайс Steam. Визуальная анимация не определяет результат; результат выбирает сервер.
- Используйте только в демонстрационной/игровой экономике без денежных выплат. Если будете вводить реальные платежи или предметы с реальной стоимостью, понадобится дополнительный аудит безопасности и юридическая проверка.
